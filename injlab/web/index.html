检测器挡得住
没见过的攻击吗？

大模型把网页、文档、邮件直接拼进提示词，而写这些内容的人不是开发者。 外围挂一个注入检测器是现在最常见的防线——但绝大多数检测器只在固定的干净测试集上报告准确率。 这个实验台要回答的是：当攻击者知道你在用检测器，并针对它改写输入时，它还剩多少能力。

01 · 数据

带难负样本的基准

良性、直接注入、间接注入三类；刻意收进"内容有害但没有覆盖指令"的难负样本， 让检测器不能靠"看起来像坏事"蒙对。

02 · 攻击

文本空间的攻击谱系

零宽字符、全角化、同形字、编码包裹、语义改写，以及在 512 token 之后的截断注入。 每一条都先判"人还读得懂吗"，只统计改完仍然可读的攻击。

03 · 防御

规范化 + 红队回路

输入规范化是确定性、零训练成本的补丁；红队回路对抗训练把新变体并回训练集。 代价与收益都在这页看得见。

提交文本做检测

检测器给出分数与逐块分数，超过阈值的片段在原文里标红。 默认 tfidf-char，它在 A1 全基线里召回最高，且不需要加载神经网络。

左侧输入或点「随机样本」，结果会出现在这里。
Cmd / Ctrl + Enter 也能直接检测。

一键剧本

顺序固定（正常 → 注入 → 绕过 → 加固 → 长文档 → 审计）， 内容每次随机：良性问题、载荷、混淆方式都会变。seed 会显示出来，点「重放上一遍」能复现同一场。

攻击谱系

同一句载荷经过不同变换后的样子。「当前分数」是实时计算的，后面的数字是相对原始载荷的跌幅—— 跌得越多说明这个变换越容易绕过它。点「试一下」会把攻击文本送进检测台。
